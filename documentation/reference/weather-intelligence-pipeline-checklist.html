Weather Intelligence Checklist

A compact, printable runbook for rebuilding and verifying the NWS-to-Lakebase vector-search pipeline.

Build and deploy

  1. Keep the application isolated under homework-2/ and the DDL in sql/schema.sql.
  2. Accept city strings and explicit coordinates; apply Nominatim identification, US restriction, caching, and one-request-per-second throttling.
  3. Resolve /points, use its returned forecast URL, and fetch point-filtered active alerts separately.
  4. Normalize alert and forecast narratives with stable IDs, content hashes, raw payloads, and source URLs.
  5. Upsert documents into weather_hw2.weather_documents.
  6. Chunk current narratives at 800 characters with 100-character overlap.
  7. Embed batches with sentence-transformers/all-MiniLM-L6-v2 using normalized 384-dimensional vectors.
  8. For each changed document/model, delete all existing chunks and batch-insert the complete current set with direct %s::vector casts.
  9. Create the document foreign key, uniqueness constraint, lookup indexes, and HNSW vector_cosine_ops index.
  10. Expose validated POST /weather/sync and POST /weather/search routes.
  11. Push main and redeploy the existing ai-support-app with source path homework-2.

Serverless job dependencies

databricks-sdk>=0.30.0,<1
sentence-transformers>=3.0.0,<6

Do not add psycopg2 packages to the job overlay. Databricks Runtime supplies native psycopg2. An overlaid psycopg2-binary wheel caused an observed SIGABRT. The separate App build still installs its own wheel.

Live verification

  1. Confirm App status is Running and GET /healthz returns HTTP 200.
  2. Sync Chicago and Austin; confirm partial failures would be reported per location.
  3. Run jobs/ingest_weather_embeddings.py and record document, chunk, and insert counts.
  4. Rerun ingestion; unchanged documents should produce zero new work.
  5. Search “flooding or severe weather risk” with top_k=5.
  6. Confirm results include location, source type, headline, chunk text, timestamps, and similarity.
  7. Run jobs/verify_lakebase_schema.py.
  8. Confirm document and embedding counts, vector(384), the document foreign key, and the HNSW cosine index.
  9. Restore the permanent Databricks task path to homework-2/jobs/ingest_weather_embeddings.py.
  10. Capture credential-free evidence and rebuild the submission ZIP without caches, virtual environments, secrets, or model artifacts.

Fast diagnosis

  • Python kernel aborts importing psycopg2: remove psycopg2 distributions from the serverless dependency overlay.
  • Python task cannot find the app package: resolve the task path from __file__ or Databricks' injected filename value and add the Homework 2 root to sys.path.
  • No search matches: verify embeddings exist for each document's current content hash and model name.
  • Vector dimension error: confirm ingestion and query both use MiniLM and emit exactly 384 values.
  • Duplicate forecasts: normalize coordinates and construct the stable ID from coordinates, period start, and period name.
  • Stale search text: compare document and embedding content hashes, then replace outdated chunks transactionally.
  • First operation is slow: allow for Lakebase scale-to-zero resume and the initial model download.
  • App URL redirects or is blocked: inspect workspace deployment status and run the equivalent Git-sourced verification task under the authenticated workspace session.
