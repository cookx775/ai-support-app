Lakebase App Checklist

A compact, printable runbook for recreating the support application in Databricks Free Edition.

  1. Push deployable source to public GitHub main.
  2. Open Lakebase Postgres Autoscaling; reuse the existing project if present.
  3. Confirm the production branch and databricks_postgres database.
  4. From branch Overview, use primary → Get ID → Copy resource name.
  5. Set that endpoint resource name as ENDPOINT_NAME in app.yaml.
  6. Create a custom Databricks App and select public GitHub branch main.
  7. Attach the Lakebase Database resource with Can connect and create.
  8. Review the App service principal authorization.
  9. Deploy manually and confirm source, spec, packages, build, and start all succeed.
  10. Open the App: load seeded tickets, create a ticket, add a message, update status.
  11. Refresh the browser and confirm every mutation persists.
  12. Use Lakebase SQL Editor to inspect both tables and the foreign key.
  13. Capture App and Lakebase screenshots; include the App URL and reflection.
  14. Restart the App before grading if its 24-hour runtime has elapsed.

Fast diagnosis

  • Endpoint not found: replace UUID-style IDs with the endpoint resource name.
  • Pool timeout after endpoint error: treat it as a downstream symptom; fix the endpoint first.
  • First request is slow: Lakebase may be resuming from scale-to-zero.
  • Push did not change the App: public Git deployment is manual; click Deploy again.
  • App stopped overnight: restart it; Free Edition Apps stop after 24 hours.
